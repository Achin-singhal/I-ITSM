## Capture guidance

- Use the live local application and actual API-backed records. Keep ticket IDs and statuses visible where possible.
- Use dedicated demo accounts and incidents. Do not expose passwords, tokens, private email addresses, or unrelated personal data. Crop or blur identifying details in a copy only when doing so does not change the application state or conceal a failure.
- Prefer one clear application state per image. Avoid browser developer tools, terminal windows, seeded-looking fabricated figures, and overlays that obscure the UI.
- Save original captures under a report media folder (suggested: `docs/screenshots/`) and insert only files that have actually been captured into the final report. The suggested filenames below are targets, not existing images.
- A screenshot proves the visible state at that moment; it does not by itself prove all earlier workflow steps, authorization boundaries, or backend persistence. Pair it with the automated/manual evidence described in the report.
